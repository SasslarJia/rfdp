# Fixed Market feature-transfer validation

Decision made after the accepted OSNet population and the coordinate/refinement audit, before any candidate TransReID query is run. The candidate equation, all graph/diffusion parameters and numerical contract remain fixed. This is a second feature representation on the same Market population, not an independent dataset or a replacement for the original experiment.

The question is whether the same degree-measure scoring adaptation remains useful with the already accepted TransReID representation. This checks empirical transfer across representations. It does not test the mass-preserving node-refinement theorem, assert duplicate-image robustness, or establish a dedicated Rank-1 optimum.

Reuse frozen Market TransReID features (MAT SHA256 ed8925dc55a02818304dcd89b40ec3a21ed7d23a5d56c62a9279b826c4a25967), its original accepted k20/gamma=.4 graph and same-feature I-HyRDP reference. Baseline mAP=94.5308903744%, Rank-1=95.2790973872%; baseline ranking SHA256 eb2f8131ecf67dd7eb996d528aa3c843c3c31405613a86336e82a1d06542f001. Verify cached inputs/reference hashes before dispatch; do not re-extract features or recompute the baseline. Missing preserved dependencies must be resolved explicitly, not silently replaced.

Run all 3368 queries against the 19732 gallery, alpha=5, beta=25, step=5, depth=500, one stationary_measure component, 16 workers and BLAS1. Use the unchanged shared compute/analysis/all-score-readback chain. No parameter search, partial-AP decisions or additional performance qualification. Retain 1e-8 actual-score residual, ordered top-five certification, exact symmetry tie rules and no numerical tail. Freeze execution Git/config/signature before launch. Runtime, peak memory and all exits come from this full run; reserve 16GiB total output and 3.5GiB AS per worker under existing system guards.

Report both mAP and Rank-1, query/identity paired 95% bootstrap intervals (10000 each, seed260626), gains/losses and cost against the same-feature original. Treat their point changes and uncertainty separately. Concordant positive points across the two feature representations support consistency of the observed direction; they do not turn intervals crossing zero into stable improvement. A discordant result requires mechanism analysis, not parameter tuning or deletion of an unfavorable result. No numerical non-inferiority margin is being claimed. The mathematical consistency property stands or falls by its stated assumptions, independently of which retrieval metric improves.

All accepted OSNet traces remain preserved. If storage is insufficient, only already stopped and fully diagnosed runs' trace intermediates may be removed after dependency/open-file/hash checks, with a receipt and explicit loss of full-score re-verifiability recorded. Do not use Elements while server cleanup suffices.
