# Fixed Market development protocol

Use the original Market input features, graph and baseline: 3368 queries, 19732 gallery images, k=20, gamma=.4, alpha=5, beta=25, step=5, depth=500. Change only the degree-weighted hybrid objective described in README.md. Keep original seed updates, bridge rules, node IDs, deterministic score/ID sorting and full-gallery tail policy. No additional strength, neighborhood or horizon parameter.

After necessary correctness checks, run the complete population directly with 16 workers and BLAS1. Do not add a performance qualification, inspect partial AP, choose a query subset by accuracy, or launch a second component/Duke. Preserve the execution Git revision and source hashes. Live admission keeps RAM below 70%, GPU below 75%, each disk free above max(25%,10GiB); output reservation is 16GiB and each worker has a 3.5GiB AS stop limit. Shared file mappings are counted once and old paused processes remain in cgroup accounting. A local size above 8192 stops rather than truncates.

The existing launcher runs compute, paired original-IHy analysis, then all-query actual-score/trajectory/ranking readback. Report all exit codes and full acceptance separately from accuracy. Report mAP, Rank-1, query and identity bootstrap 95% intervals with 10000 replicates and seed260626. A positive mAP point difference is a Market development point improvement; intervals excluding zero on the positive side support stable gain under this protocol. A negative point difference alone is not significant harm. Runtime and memory come from the natural formal run.

If the fixed form does not improve, analyze the accepted full result and a bounded common-prefix mechanism comparison before a different justified single-component experiment. Do not expand a strength grid or repair numerical failure by changing the objective. Keep necessary failure evidence; clean obsolete intermediate traces only after dependency/open-file/hash checks, and record loss of full-score re-verifiability if they are deleted.
